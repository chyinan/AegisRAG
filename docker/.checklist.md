### ✅ 软件环境

- [ ] **Docker Desktop for Windows** 已安装并运行

- [ ] PowerShell 5.1+ 或 PowerShell 7+ 

### ✅ 文件准备

- [ ] `.env` 文件存在且配置正确
- [ ] `docker/compose.yaml` 未被意外修改
- [ ] `apps/api/`, `apps/web/`, `apps/worker/` 目录完整

### ✅ Docker Compose 验证

```powershell
# 使用 env 文件验证 compose 配置 (脱敏输出)
docker compose --env-file .env -f docker/compose.yaml config --services
```

如果看到：
```text
Services:
  api, web, worker-ingestion, postgres, redis, minio...
```
✅ **通过!**

**失败处理**:
- `✖ POSTGRES_PASSWORD 不是必须的 → 编辑 .env`
- `✖ MINIO_SECRET_KEY is required   → 编辑 .env`

## 🔧 部署步骤

### Option A: 一键启动脚本 (最简单)

```powershell
# 使用批处理脚本 (Windows 用户推荐)
.\scripts\start.bat
```

```powershell

docker compose --env-file .env -f docker/compose.yaml up -d --build \
    postgres postgres-roles redis minio migration api web worker-ingestion worker-embedding
```

### Option C: PowerShell 脚本 (可配置)

```powershell
# 验证配置并启动
.\<PSScriptRoot>\validate-and-start.ps1
```

## 🚫 常见问题与解决

### Problem: `API /ready=false`

**症状**:
```powershell
curl http://localhost:8000/ready  # ready=false error_code=...
```

**可能原因**:
1. PostgreSQL 没有健康 (最常见) → `docker compose exec postgres psql -U rag_runtime -d rag_app -c "SELECT version()"`
2. MinIO bucket 不存在 → `docker compose logs minio-init`
3. JWT secret 太长或包含非法字符

**解决**:
```powershell
# PostgreSQL 确保健康
docker compose exec postgres pg_isready -U rag_runtime -d rag_app || restart api

# MinIO 初始化失败时重启
docker compose restart minio-init
```

### Problem: `Web UI 502 Bad Gateway`

**症状**:
```powershell
curl http://localhost:3100/  # 返回 502 Bad Gateway
```

**可能原因**:
- API 服务未就绪但 Web 已启动
- Next.js 编译失败 (Dockerfile.web 错误)

**解决**:
```powershell
# 查看前端构建日志
docker compose logs web | Select-String "Error" | Select-Object -First 50

# 如果是 build 失败，检查 Dockerfile
docker compose up -d --build web

# 确保 API 健康后重启 web
docker compose restart api
docker compose restart web
```

### Problem: `容器反复重启`

**症状**:
```powershell
docker compose ps | Select-String "Exit" # 显示退出状态码!=0
docker compose logs api --tail=200 | Select-String "Traceback\|Error\|Exception"
```

**解决**:
1. 查看错误 → `docker compose logs api`
2. 常见错误：数据库连接失败、端口冲突、认证失败
3. 重置状态 → `docker compose down -v && start.bat`

## 🛡️ 数据持久化与备份

### Volume 说明

| Volume | 用途 | 删除此 volume 的影响 |
|--------|------|---------------------|
| `postgres-data` | PostgreSQL + 向量数据库 | **所有文档数据丢失** ⚠️ |
| `redis-data` | 缓存、队列状态 | Redis 重启后重新初始化 |
| `minio-data` | 对象存储 (文档) | 所有上传的 document blobs 丢失 ⚠️ |

### 备份命令

```powershell
# PostgreSQL dump (包含 schema + 数据)
docker compose exec postgres pg_dump -U rag_runtime rag_app > backup.sql

# Redis RDB snapshot
docker compose exec redis redis-cli BGSAVE

# MinIO 文件备份 (需 mc 工具安装)
mc config host add aegis http://localhost:9000 minioadmin <minio-password>
mc ls aegis/documents
```

## 🔄 更新与迁移

### 仅重载某个服务

```powershell
# 重新构建并启动特定服务
docker compose up -d --build api web
# workers 通常不需要 rebuild(除非 pyproject.toml 变更)

# 重启 postgres (谨慎!只用于 schema 变更)
docker compose restart postgres-roles
docker compose down -v postgres || docker compose up -d postgres && docker compose exec postgres pg_isready
```

### Schema 迁移

```powershell
# 数据库结构变更时：Alembic upgrade 自动执行
# 如果失败：检查 .env 中的 DATABASE_URL schema 匹配迁移版本
docker compose restart migration
docker compose logs migration | Select-String "error"
```

## 📝 安全提醒 (生产环境)

部署到生产前完成:

- [ ] 更换所有 `replace-with-...` 占位符为真实值
- [ ] 使用 HTTPS (添加 Traefik/NGINX TLS 终止)
- [ ] 设置合理的 `RATE_LIMIT_*` 限制
- [ ] 禁用 Dev auth headers：`ENABLE_DEV_AUTH_HEADERS=false`
- [ ] MinIO 存储 ACL 设置为 private (不是 public-read)
- [ ] Grafana 使用强密码并移除默认用户
- [ ] 定期备份 `postgres-data`, `minio-data`, `redis-data`, 和 HuggingFace caches
