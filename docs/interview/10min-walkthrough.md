# 10 分钟技术展示：从用户闭环到失败恢复

这是一份基于当前实现的讲解提纲，不代表个人履历、团队经历或线上成果。
只使用自己能解释、能运行并有实际贡献的部分。演示前记录代码版本、依赖版本、
运行命令和测试结果；不要引用旧文档的行数或把 MockTransport 当成真实模型。

## 0–2 分钟：先展示一条用户路径

主界面是 Next.js 工作台，后端是 FastAPI。先讲清楚使用者能完成什么：

1. 使用已有身份进入工作台，导航和动作按权限显示
2. 上传文档，查看解析、分块、Embedding 与索引状态
3. 通过流式问答看到回答与引用，再打开引用查看当前权限下的源证据
4. 在 Agent Runs 中使用普通执行、实时工具进度或显式 durable 审批恢复模式

不要把“上传返回成功”说成“可检索”：异步流水线有独立状态，向量、版本和索引
就绪需要后续确认。也不要把 `/ready` 或一张截图说成端到端验收。

源码入口：

## 2–4 分钟：解释业务边界，而不是只列技术栈

### 权限与引用

请求身份来自应用认证上下文。检索结果在进入模型上下文前经过租户、权限与文档
可见性约束；引用保持文档、版本、chunk 的身份。打开引用仍要在当前身份下解析，
不能因为过去见过回答就跳过权限变化或文档删除。

### 框架接入

原生实现仍是默认项，LLM、Embedding、Agent 调度是三个独立开关。LangChain
ChatOpenAI/Embedding 适配器实现已有端口，受控 Retriever/Runnable/StructuredTool
把应用能力交给框架组合；LangGraph 是真实状态图，但没有接管业务策略。

模型原生工具调用只产生一条声明式决策，工具仍由同一 ToolRegistry 执行。
没有另起一个不受原预算约束的框架 agent loop。同步线程替代应用异步会话、
任意工具/任意 provider 的“通用接入”都不在支持范围内。

展示 [能力矩阵](../FRAMEWORK_ADAPTERS.md) 中的八种组合测试，再指出框架事件、
回调和环境 tracing 不能自动获得原始输入、工具内容或认证信息。Token usage
拿不到时保留不可用状态，不猜一个数字。

## 4–7 分钟：用一次审批解释 durable 的难点

以 calculator 的合成输入为例：

1. 创建运行时确定原始 deadline 和步骤/工具预算
2. 模型提出工具动作，系统展示确切工具、参数、审批标识和定义摘要
3. 用户选择批准前，UI 先读当前状态；若状态、修订号、参数或期限变化，要求重新查看
4. 服务端再次鉴权并以修订号 CAS 和租约取得执行权
5. 工具调用前记录账本，完成结果与下一业务状态原子提交
6. 最终回答完成引用校验且终态提交成功后，才可展示

这里可以回答三个追问：

- **为什么不是直接打开框架 checkpointer？** 原先闭包里的运行状态不是可恢复
  业务快照。当前私有快照保存版本、预算、重复动作状态和证据引用；真实 LangGraph
  checkpoint 只保存路由与不透明业务引用，不序列化 prompt、对象或认证上下文
- **进程在工具执行后退出怎么办？** 已提交结果不重新执行。未确认结果的只读工具
  只能按策略和剩余预算重放；不可重放副作用进入 `intervention_required`。
  没有外部系统幂等/事务协作，就不能承诺通用 exactly-once
- **初次响应丢失怎么办？** 可选 UUID4 启动 key 绑定 tenant/user 和确切命令。
  重复启动是读取，不是再执行；按 key 恢复也是只读。保留的 tombstone 防止私有
  快照过期后用同一 key 重建运行，但保证受 tombstone 保留期限制

原始墙钟期限包含审批等待和进程停机，恢复不会重置预算。权限、证据内容和工具
定义变化都可能阻止继续执行。取消只能确认已提交的终态，不能撤回外部副作用。
[架构决策](../adr/0009-governed-framework-and-recovery.md) 记录这些取舍，
[durable 操作指南](../operations/DURABLE_AGENT.md) 记录升级、回滚与保留边界。

## 7–9 分钟：展示故障行为与用户体验

工作台默认一次性执行；实时模式展示工具开始/结果，不能把进度当作回答。
流中缺少终态、协议顺序异常或连接中断，会显示不完整结果。停止等待不是服务端
持久取消回执。已知 durable 运行只有收到 `cancelled` 响应才显示确认。

可以选两项失败注入测试现场运行，而不是修改真实业务数据制造故障：

- 审批过期、修订号冲突或权限/证据变化：不能把旧批准转交给新动作
- 子进程在工具结果提交后硬退出：新进程恢复，已提交结果不重复执行
- 取消与终态持久化失败：不得输出未经确认的完成或取消状态
- 审计/进度依赖卡住：辅助 I/O 有界；必需账本、工具记录和终态写入仍 fail-closed

审计投递有明确的 best-effort 边界，不能宣称每个事件一定送达。辅助审计使用独立
会话，避免超时取消污染必需事务。外部客户端仍需要自身超时和取消响应能力。
详情见 [工作台指南](../operations/AGENT_WORKBENCH.md) 和
[辅助 I/O 边界](../operations/AGENT_AUXILIARY_IO.md)。

## 9–10 分钟：展示证据分层和剩余验收

| 证据 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 八组合、真实框架与本地传输 | 支持版本下业务契约保持一致 | 所有 provider、真实模型质量或性能 |
| SQLite、真实图、独立进程故障注入 | 已覆盖的恢复/预算/账本行为 | PostgreSQL 锁、RLS、跨主机故障转移 |
| 前端协议/组件测试、类型检查与构建 | 已覆盖的 UI 状态和可构建性 | 浏览器布局、可访问性、代理断连行为 |
| 已编写 PostgreSQL CI gate | 有明确的运行角色、迁移和 RLS 验收入口 | 该 gate 在目标环境已经通过 |

目标环境仍需验证真实认证、PostgreSQL/RLS 并发、备份恢复、保留策略、反向代理
流式行为、真实模型兼容性与浏览器体验。历史 judge 分数和延迟数据不能作为本轮
改动的提升结果。结束时给出实际测试报告与未验证项，不用“生产就绪”替代证据。
